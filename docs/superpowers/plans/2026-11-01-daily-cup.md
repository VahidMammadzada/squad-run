# Daily Cup, Weekly League and Rival Kits Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a once-a-day seeded cup that scores points in a simulated 8-club weekly league, pays fans at the end of the season, and shows rival kits on defenders and keepers.

**Architecture:** All rules are pure in `src/club/league.ts` (time, rivals, scoring, table, payout) and `src/game/levelGen.ts` (day-seeded layout), unit-tested with `now` passed in. Persistence is a small `league` block in the save (v6) driven through `Progress`. The cup is a mode of `GameScene` (`cup` init data) that never calls `completeLevel`/`failRun`; a new CUP stall opens a bottom sheet, unlocked at level 4.

**Tech Stack:** TypeScript (strict), Vitest, Phaser 3, Three.js. Work on a new branch off `visual-overhaul`.

**Spec:** `docs/superpowers/specs/2026-11-01-daily-cup-design.md` (also read `CLAUDE.md`).

## Global Constraints

- Fans only go up; the score sent via `sendScore` equals `fans` in the save and is sent only after a successful save (follow `Progress.completeLevel`).
- `sanitizeSave` never throws; bump `SAVE_VERSION` 5 → 6 and read the v5 shape.
- `generateLevel(n)` output must stay identical (existing tests plus a golden test added in Task 5).
- Pure logic imports neither Phaser nor Three; all date logic takes `now` (ms) as an argument; day and week are UTC; week starts Monday 00:00 UTC.
- Cup unlocks at `level >= 4` (`CUP_UNLOCK_LEVEL`); before that no CUP stall and no league data.
- Cup runs do not touch `level`, star fitness, injuries, campaign timers or merch; no revive; no rewarded ads; no new network calls; fictional names only.
- League: 8 clubs (player + 7 rivals), 7 daily cups per season. Daily score out of 5: result 0–3 (win 3, draw 1, loss 0), squad bonus 0/1, goals bonus 0/1.
- Only the first run that reaches the shootout each day scores; later runs are practice. Dying before the shootout does not use up the day.
- Visuals follow `.claude/skills/art-direction`; verify with `.claude/skills/capture-game`.
- Prices, payouts and thresholds live in `src/club/balance.ts`.
- Commit messages end with `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`.

## Review Focus

- Device clock earlier than the stored season: nothing lowered, nothing paid twice (Task 3 test).
- Corrupt, missing or v5 `league` data in a save: `sanitizeSave` yields a valid empty league (Task 6 test).
- A cup that starts before UTC midnight and ends after: scored for the start day (Task 3 and 9 tests).
- Season rollover: a previous season with at least one cup pays once; reopening never pays again; no cups pays nothing (Task 3 test).
- Cup game over: `failRun` and star state untouched, RETRY stays in cup mode (Task 9 test).
- A second scored attempt on the same day, or a cup at level 3, changes nothing (Task 3 and 10 tests).

### Task 3: Cup scoring, table, season state and payout

**Files:** Modify `src/club/league.ts`, `league.test.ts`.

**Interfaces:**
- Consumes: Tasks 1–2; `SEASON_PAYOUT`, `CUP_*` from balance.
- Produces:
  - `interface CupDay { day: number; points: number }`
  - `interface LeagueState { seasonId: number; cups: CupDay[]; paidSeason: number }`
  - `emptyLeague(): LeagueState` (`seasonId: 0, cups: [], paidSeason: 0`)
  - `scoreCup(i: { goals: number; rivalGoals: number; squad: number; parSquad: number }): { result: number; squadBonus: number; goalsBonus: number; total: number }` (squad bonus when `squad >= parSquad`; goals bonus when `goals >= CUP_GOALS_BONUS_MIN`)
  - `canScoreCup(state: LeagueState, now: number): boolean` (false if `state.seasonId !== seasonIdOf(now)` or today already in `cups`)
  - `recordCup(state: LeagueState, startedAt: number, points: number): LeagueState` (returns the same state if `seasonIdOf(startedAt) !== state.seasonId` or that day is already recorded)
  - `interface TableRow { name: string; points: number; isPlayer: boolean; place: number }`
  - `leagueTable(state: LeagueState, daysElapsed: number, playerName: string): TableRow[]` (rival points summed over days `0..daysElapsed-1`; ties: fixed rival order, player ahead of equal rivals)
  - `seasonPayout(place: number): number`
  - `rollSeason(state: LeagueState, now: number): { state: LeagueState; payout: number; place: number | null }`: if `state.seasonId > seasonIdOf(now)` returns unchanged with payout 0; if equal returns unchanged; if the stored season is older and has at least one cup and `paidSeason < state.seasonId`, pays `seasonPayout` for the final place (table over `SEASON_DAYS`); then returns a fresh state for the current season with `paidSeason` set to the stored season id.

- [ ] **Step 1: Write failing tests:** `scoreCup` with goals 3 vs rival 2 gives result 3; 2 vs 2 gives 1; 1 vs 2 gives 0 with goals bonus 1; squad bonus only at or above par; total never exceeds 5. `canScoreCup` false on a second call for the same day and true on the next day. `recordCup` ignores a second record for the same day and a record from another season. Table has 8 rows, places 1..8, player ahead of an equal-points rival. `rollSeason`: a finished season with one cup pays once and a second `rollSeason` call at the same `now` pays 0; a season with no cups pays 0; `now` earlier than the stored season returns the state unchanged with payout 0; skipped seasons pay only the stored one. A cup started at `2026-11-01T23:59:00Z` and recorded with `startedAt` of that time lands on day 6 of its season even if `now` is already the next Monday.
- [ ] **Step 2:** Run; expect FAIL.
- [ ] **Step 3:** Implement the functions above. The pay-out amount must be a plain number from `SEASON_PAYOUT`, never negative.
- [ ] **Step 4:** Run; expect PASS.
